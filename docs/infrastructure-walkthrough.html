Technical walkthrough

Infrastructure architecture & deployment

Logic App AI Accelerator: a subscription-scoped Bicep deployment that stands up a web/API app, a Logic Apps Standard workflow, and Azure AI services, then runs a PDF → summary → search pipeline on top of it.

networkMode: public | private monitoringMode: none | new | existing azd or GitHub Actions Managed identity, no secrets

Purpose

An application-focused starting point. It does not recreate PBMM / Azure Landing Zone services — private mode plugs into existing subnets, NSGs, routing and private DNS.

Repeatable infra

One main.bicep creates three resource groups, data, compute, AI, monitoring and every RBAC grant.

Workflow-orchestrated AI

Logic App detects a new PDF and calls the API, which uses Document Intelligence, Foundry and AI Search.

Secure by default

Managed identities and data-plane RBAC throughout; private endpoints and disabled public access in private mode.

Azure infrastructure architecture

Resources by resource group, with numbered interactions. Dashed items apply only to a given mode or option.

  1. 1 Users reach the web app over HTTPS (optional Entra sign-in).
  2. 2 The API stores jobs in Cosmos DB and PDFs in Blob Storage.
  3. 3 A new blob triggers the Logic App workflow.
  4. 4 The workflow calls the API using its managed identity.
  5. 5 The API calls Foundry, Document Intelligence and AI Search with Entra tokens.
  6. 6 Diagnostics and telemetry go to Log Analytics (unless monitoring is none).
  7. 7 azd or GitHub Actions deploys infrastructure, the container image and the workflow zip.

Public mode

Public endpoints; optional IP allow-list (default-deny when set).

Private mode

Public access disabled, private endpoints, VNet integration, all-traffic routing. Needs 4 distinct subnets and every private DNS zone.

App Service auth

Optional Entra sign-in; federated credential on the web identity, no client secret. /api/health is exempt. FTP/SCM basic credentials are restricted by policy resources.

Dependencies

Tooling

Azure CLI / azd, Bicep, Python 3 (azd hooks), Docker build via ACR Tasks, Node (Logic project).

Azure prerequisites

Subscription deploy rights plus permission to create role assignments; Entra rights if app registration is used.

Private mode inputs

Existing subnets (private endpoint, web, Logic, agent), private DNS zones, Premium ACR, and a runner that can reach the private SCM endpoints.

Error handling

WhereBehaviour
Bicep parametersInvalid combinations call fail() at deployment start with a clear message (missing subnets or DNS zones, non-Premium ACR in private mode, bad SKU for ASE, mismatched chat deployment).
Upload APIStructured JSON {error:{code,message}}: 400 missing/empty, 415 non-PDF, 413 too large, 404 unknown job; any unhandled exception → generic 500 (logged server-side).
Logic → API callExponential retry, 4 attempts (5 s min, 5 min max). Then Handle_Processing_Failure captures run id and results and terminates the run Failed.
Hooks & teardownOrphaned Disconnected AMPLS endpoints are repaired before provisioning; AMPLS removed before down; soft-deleted AI accounts purged only if AZURE_PURGE_SOFT_DELETED_ON_DOWN=true (otherwise redeploy fails with FlagMustBeSetForRestore).
Storage policyIf the subscription forces storage public access to Disabled, Logic host storage is unreachable in public mode — use private mode.
Known gap (from the code)

If process() throws after the job is set to processing, the API does not write a failed status. The Logic App run shows Failed, but the UI keeps polling a job that stays processing. Support should check Logic App run history and App Insights.
