Technical walkthrough

Infrastructure architecture & deployment

A subscription-scoped Bicep deployment (infra/main.bicep) that provisions an application tier (App Service + Logic Apps Standard), data tier, Azure AI services and optional monitoring across three resource groups. Public and private networking are one parameter apart.

networkMode: public | private monitoringMode: none | new | existing aiResources.*.mode: new | existing azd or GitHub Actions Entra ID auth only, no keys

Design principles

Application-scope accelerator. It does not recreate PBMM / Azure Landing Zone services; private mode plugs into existing subnets, NSGs, routing, egress controls and private DNS.

Subscription-scope IaC

Creates the resource groups, then modules per tier. Typed parameters (types.bicep) and fail() guards reject invalid combinations before anything deploys.

Identity-first security

User-assigned managed identities, data-plane RBAC, shared keys and local auth disabled on Storage, Foundry and Search.

Bring your own platform

Reuse existing Foundry, Document Intelligence, AI Search and monitoring by resource ID, including across subscriptions.

Network topology: public vs private

Private mode integrates with an existing VNet and DNS. The accelerator creates private endpoints and DNS zone groups, never the network itself.

Required subnets (distinct)
  • Private endpoint subnet
  • Web app VNet integration subnet
  • Logic App VNet integration subnet
  • Agent subnet, delegated to Microsoft.App/environments (Foundry agent network injection)

Web and Logic integration subnets are not needed when that app uses an ASE.

Private endpoints (group IDs)
  • Storage ×2: blob, file, queue, table
  • Cosmos DB (SQL), ACR, App Service sites
  • Foundry, Document Intelligence, AI Search
  • AMPLS: monitor, oms, ods, agentsvc
Private DNS (supplied, not created)

Zone IDs per service: blob, file, queue, table, cosmosSql, acr, sites, cognitiveServices, openAi, aiServices, search; plus monitor, oms, ods, agentsvc for new monitoring. Provide one resource group or a JSON map (sovereign clouds).

  • Foundry, Search: disableLocalAuth

  • httpsOnly, TLS 1.2, FTPS disabled
  • FTP and SCM basic auth disabled by policy resources

  • /api/health excluded

Dependencies, ordering & failure modes

Tooling

Azure CLI, azd, Bicep, Python 3 (hooks), ACR Tasks (remote build), Node (Logic project).

Azure permissions

Deploy at subscription scope and create role assignments (also on existing AI resources). Entra app-registration rights for Easy Auth.

Ordering constraints

Model deployments serial (@batchSize(1)); project roles after the capability host; infra before image and workflow deploy.

Failure modeBehaviour and mitigation
Invalid parametersfail() at deployment start: missing subnets or DNS zones, non-Premium ACR in private mode, non-Isolated SKU with ASE, Logic plan not WS1–WS3, bad chat deployment name, duplicate subnets.
Soft-deleted AI accountsRedeploy fails with FlagMustBeSetForRestore. Set AZURE_PURGE_SOFT_DELETED_ON_DOWN=true so postdown purges; off by default to keep recovery.
AMPLS endpoint DisconnectedCannot be updated by Azure; preprovision deletes it. predown removes AMPLS so the workspace can be deleted.
Storage public access forced Disabled by policyLogic host storage unreachable in public mode; use private mode.
Existing AI resourceMust allow Entra auth (Search RBAC on); no Foundry project or capability host is created; public access is left as is.
azd hook failurecontinueOnError: false stops the run. The GitHub workflow skips hooks, so create the app registration separately.
